SoundCloud · Profile header

SOC-06 · 2480 × 520 · soundcloud.com/theflir

The banner behind the profile at soundcloud.com/theflir. It is not a surface the site sends anyone to — public/index.html deliberately does not link the profile, and that call stands. This exists for the people who are already there: arriving from SoundCloud search, and from the embedded players on /music, whose chrome links back to the profile whether the site wants it to or not. That traffic was landing on a header that predates this system.

Rules

The artwork lives in social/soundcloud-header.export.html — a bare 2480×520 page with no card chrome, embedded above. This card documents it and never re-draws it, so the preview and the shipped PNG cannot drift apart.

The type position is derived, not chosen. SoundCloud accepts 1240 as a minimum width, so 1240 is also the only width worth trusting — narrow viewports and the app crop inward from both edges, leaving the centre 1240 (x 620–1860). It also draws the avatar and artist name over the lower left (x 0–880). Intersect the two and the only region that survives both is x 880–1860. The mark sits right of centre because that is where it is allowed to be.

The left of the field is flat and quiet by design. That is not empty space — it is what SoundCloud's avatar and artist name have to stay legible on top of.

GDL-07 stack in order: image, crush, hard grain, scanline, then type. The grain layer stops under the type layer.

The field is flirbackground.jpg, the same field as the og:image — the two surfaces where someone meets THE FLIR cold should be the same field. It is already lit red, so it takes --flir-photo-filter-native rather than the grayscale pass. That field is the one red on this surface — nothing in the type layer may be red, so there is no rule and no mark.

The wordmark is .flir-wordmark, never re-typed by hand. Its locked 1:2 construction only holds if both local faces load, which is why this renders over http and not file:// — see the deviation opposite.

The credit is the one element deliberately outside the guaranteed band. A credit is not orientation, so a narrow crop may take it and nothing is lost.

No release title, no date. A surface that names a record has to be re-rendered the day that record stops being current, and it never is — which matters more here than anywhere, since the newest upload on this profile is from 2015.

Render

Deviation · source narrower than the canvas flirbackground.jpg is 1024px wide and this canvas is 2480, so the field is carrying a 2.42× upscale. It holds because GDL-07's pass is a degradation treatment — 2px hard grain reasserts high-frequency detail across the whole surface and the softness underneath stops reading. Verified by eye at full size, not assumed. If the field is ever swapped for one where it does read, suture8-01-cover-full.png needs only 1.55×.
Deviation · horizontal framing is not available Under cover, a 1024-wide source fills a 2480-wide canvas exactly, so the horizontal half of background-position does nothing at all. Only the vertical band can be chosen. Anyone re-framing this surface will reach for the X value first; it is inert.
Deviation · http, not file:// The export page must be served over http. From file://, the local @font-face TTFs are blocked, Placard Condensed and Frankfurter both fall back to Impact, and the wordmark ships wrong at the one size where it is most visible. The failure is silent — the render succeeds and merely looks off.
Deviation · scale factor 1 --force-device-scale-factor=1 is not optional on a Retina Mac. Without it Chrome renders at 2x and writes a 4960×1040 file, which SoundCloud will accept and then resample.

The safe-area figures in tokens/layout.css are working values read off the live profile. SoundCloud has changed this layout before and will again — re-check them against the real page before a re-render, rather than trusting the diagram above.
