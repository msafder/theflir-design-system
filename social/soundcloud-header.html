SoundCloud · Profile header

SOC-06 · 2480 × 520 · soundcloud.com/theflir

The banner behind the profile at soundcloud.com/theflir. It is not a surface the site sends anyone to — public/index.html deliberately does not link the profile, and that call stands. This exists for the people who are already there: arriving from SoundCloud search, and from the embedded players on /music, whose chrome links back to the profile whether the site wants it to or not.

Rules

The artwork lives in social/soundcloud-header.export.html — a bare 2480×520 page with no card chrome, embedded above. This card documents it and never re-draws it, so the preview and the shipped PNG cannot drift apart.

No wordmark on this surface. SoundCloud sets the artist name in its own UI immediately to the left, and the avatar carries the real GDL-05 lockup. A third instance inside the same 1500px made the name stutter and stood the platform's generic sans directly beside the brand's own construction, inviting a comparison nobody wins. The avatar is the surface that has to identify the band. This one does not, so it stops trying.

Two crops, pulling opposite ways. Desktop puts the avatar and artist-name block on top of the banner out to x 990, at close to full height — a left column, not a lower-left corner. Mobile web does the reverse: it crops hard and is left-anchored, showing only the first ~1747px and discarding the right 710. Neither edge is where SoundCloud's published 1240 minimum suggests.

So the usable region is the intersection, not either constraint alone: x 1080–1680. That is 600px of a 2480px canvas, and it is fixed in both directions — move left and the desktop chrome lands on the type, move right and mobile throws it away. Everything outside that window is field. Nothing load-bearing may go there, including the credit.

Same field as the homepage. dbnelson-09 under --flir-photo-filter is what web/hero.html runs, and a profile header and a site homepage are the same object — the top of a page about the band. The og:image uses the red flirbackground instead, but that is a 1.91:1 card appearing inline in a chat, which is a different job. Matching the og:image here left the banner clashing with its own avatar.

The orientation line is split across two lines because it has to be. Set as one line it drops to about 29px to fit 600px, which is thin at this size. Split, the URL — the only actionable thing on the surface — becomes the largest type on it.

Layer order follows the hero: image, grime, crush, grain, scanline, vignette, then type. The grain layer stops under the type layer.

One red: the rule. Because the field is greyscale here, a red element is available — unlike the og:image, where the field itself is the surface's one red. Nothing else may be red.

No release title, no date. A surface that names a record has to be re-rendered the day that record stops being current, and it never is — which matters more here than anywhere, since the newest upload on this profile is from 2015.

Measured, not assumed The chrome figures come off the live profile on 2026-08-09, after a first version was built on guessed ones and shipped a visible collision: the artist-name block overlapped the banner's own type. The overlay opposite exists so the next person checks rather than reasons. SoundCloud has changed this layout before and will again — re-measure before a re-render.
The 1240 minimum is not a crop guarantee SoundCloud publishes 1240 as the minimum accepted width. It describes neither crop. Desktop does not crop horizontally at all — the banner is letterboxed at full 4.8:1. Mobile web crops hard and is left-anchored, not centred: measured on iOS Safari the banner rendered 924 × 275 css px, which is scale 0.529 against this master, so the visible region is x 0–1747 and the right 710 are discarded. Solved from the render, not estimated. The SoundCloud native app is still unmeasured; it may differ again.
The band is measured, not eyeballed Mean luminance was sampled inside the type window across the full range of vertical positions. top is both darkest (mean 34) and flattest (peak 132), while the mid bands run 54–60 with peaks over 230 and swallowed the smaller line outright. Re-run that sample if the field is ever swapped — picking a band by eye is how the previous two versions went wrong.
Deviation · horizontal framing is not available Under cover, a 1200-wide source fills a 2480-wide canvas exactly, so the horizontal half of background-position does nothing at all. Only the vertical band can be chosen. Anyone re-framing this surface will reach for the X value first; it is inert.
Deviation · hard grain where the hero uses soft The hero runs --flir-grain. This runs --flir-grain-hard at .45, because it carries a 2.07× upscale across a canvas more than twice the hero's width and the soft grain leaves the flat areas visibly smooth at that size.
Deviation · red rule sized off-token 10 × 300px, not a border token. Follows the story master's red-rule grammar (8 × 240 at 1080 wide) fitted to the 600px window; --flir-border-heavy at 4px is a hairline at 2480 and reads as a rendering error.
Deviation · http, not file:// The export page must be served over http. From file://, the local @font-face TTFs are blocked and Placard Condensed and Frankfurter fall back to Impact. No wordmark ships on this surface, so the damage is smaller than elsewhere — but the mono face degrades too, and the failure is silent.
Deviation · scale factor 1 --force-device-scale-factor=1 is not optional on a Retina Mac. Without it Chrome renders at 2x and writes a 4960×1040 file, which SoundCloud will accept and then resample.
